Section 2 — Suggested Improvements
-----------------------------------

### Skills

**A. Add a `prompt-caching-hygiene` reference skill — High impact, certain confidence**

- **What:** New reference skill (or expansion of `claude-api`) that captures the cache-hygiene rules from the Claude Code post: stable prefix ordering, no mid-session model switches, static tool sets via deferred loading, system-reminder injection over CLAUDE.md mutation, cache-safe compaction.
- **Why:** The Claude Code team treats cache hit rate as a SEV-tier production metric. The user's setup has many moving pieces (skills, hooks, MCP, ToolSearch) and currently has no explicit guard against the most expensive cache-busting patterns. The user already pays for Opus 4.7 (1M context); cache misses are particularly expensive at this tier.
- **How:** Reference skill that the agent reads when (a) about to switch models (e.g., `/fast`), (b) about to mutate CLAUDE.md mid-session, (c) about to add or remove an MCP server mid-session. Could also add a "before suggesting a model switch, warn about cache implications" rule to global CLAUDE.md.
- **Impact:** High (cost + latency on long sessions). **Confidence:** Certain.

**B. Audit `/fast` slash command for cache-bust warning — High impact, likely**

- **What:** The `/fast` toggle switches Opus 4.7 ↔ Opus 4.6. Per the caching post, mid-session model switching invalidates the entire conversation's cache and "continuing with Opus is cheaper than switching to Haiku after 100k tokens."
- **Why:** Without an explicit warning, the user may toggle `/fast` deep into long sessions and silently pay the cache-rebuild cost.
- **How:** Have the agent surface a one-line warning when the user invokes `/fast` mid-session: "Cache will be invalidated; ~$X cost to rebuild at current context size. Confirm?" — implementation likely lives in a hook on the toggle command.
- **Impact:** High on long sessions, low on short. **Confidence:** Likely (depends on whether `/fast` is invoked enough to matter).

**C. Apply MacLean's explicit auto-load triggers to high-stakes skills — Medium impact, likely**

- **What:** MacLean adds conditions like "ALWAYS load when investigating bugs" to essential skills. Inspect the user's most critical skills (`software-engineer`, `systematic-debugging`, `verification-before-completion`) and verify their `description:` fields contain forcing language strong enough to fire reliably.
- **Why:** The user's CLAUDE.md already mandates these via `MANDATORY` text in the routing entries — but the skill descriptions themselves are what the harness uses for invocation decisions. Belt-and-suspenders.
- **How:** Audit description frontmatter; tighten weak-trigger phrasing where present. The `software-engineer` skill (already MUST-be-invoked) is the model.
- **Impact:** Medium. **Confidence:** Likely — depends on what audit reveals.

### MCP

**D. Audit Todoist MCP server against the production-systems patterns — Medium impact, likely**

- **What:** The user runs a Todoist MCP. Compare its tool surface against the new MCP guide: are tools grouped by intent or mirroring the Todoist REST API? Is tool search supported? Are tool descriptions complete enough that fewer-better tools beat exhaustive surface?
- **Why:** Tool search reduces tool-definition tokens 85%+; intent-grouped tools outperform exhaustive API mirrors. The user's prompt cache benefits compound when the MCP surface is small and stable.
- **How:** This is upstream work — the MCP server likely isn't authored by the user. Worth checking which Todoist MCP they're using, and whether it's worth either contributing improvements or wrapping it with an intent-shaped facade.
- **Impact:** Medium (token-cost on every Todoist-using session). **Confidence:** Likely.

### AgenC Configuration

**E. Investigate per-mission config rebuild as a cache-bust trigger — Medium impact, speculative**

- **What:** Per `claude-config/CLAUDE.md`, every `agenc mission reload` rebuilds the per-mission config snapshot from staging. The caching post says "static tool sets" and "stable prefix ordering" are foundational — if the rebuild produces byte-identical config when nothing has changed upstream, no problem; if it introduces nondeterministic ordering, every reload is a cache miss across the prefix.
- **Why:** The user's workflow uses `--async` reloads heavily for config propagation. If reloads are silently cache-busting even when no config has changed, this is a tax on long-running missions.
- **How:** Verify the AgenC wrapper produces deterministic config output across rebuilds. Likely a quick check on the staging→snapshot pipeline.
- **Impact:** Medium if reloads are frequent. **Confidence:** Speculative — depends on AgenC internals.

### Workflows

**F. Adopt the "Outcomes" rubric-grader pattern in `/council` — Medium impact, likely**

- **What:** Anthropic's new Outcomes feature uses a *separate* grader agent in its own context window evaluating against a developer-defined rubric, with the original agent re-attempting on failure. Internal testing showed +8.4–10.1% task success on document-generation tasks. The user's `/council` skill already runs proposers + judges, but the architectural specifics of "grader in separate context, rubric explicit, automatic re-attempt loop" may sharpen what `/council` does.
- **Why:** Convergent evidence that this pattern raises quality. Cheap to incorporate if `/council`'s judge phase isn't already structured this way.
- **How:** Review `/council`'s judge prompt for explicit rubric structure; if missing, add. Add a re-attempt loop where proposers re-do work after judge feedback (if not already present).
- **Impact:** Medium on high-stakes outputs. **Confidence:** Likely — net positive even if `/council` is already close.

**G. Schedule a recurring `/self-refine` via the existing `/schedule` skill — Medium impact, likely**

- **What:** The Managed Agents "Dreaming" feature is essentially scheduled, batched self-improvement reviewing past sessions. The user has `/self-refine` (per-session) and `/schedule` (cron-based remote agents). Combine them: run `/self-refine` on a weekly schedule against recent transcripts to surface drift before it accumulates.
- **Why:** Self-refine currently runs only when manually invoked. Friction patterns that would warrant a structural fix go un-fixed if the user doesn't think to invoke it. A scheduled pass catches the long tail.
- **How:** `/schedule` a weekly remote agent that reads the last week of session transcripts (`agenc session ls` + `agenc session print`) and runs `/self-refine` against them, opening a beads issue or PR with proposed CLAUDE.md/skill/hook changes for review.
- **Impact:** Medium. **Confidence:** Likely.
