Every cron in the fleet (flight-watcher, daily-state-summary, hn-daily-pull) has the same exposure. The Claude Tag on-call post is adjacent evidence that Anthropic treats "first responder tells you something broke" as its own layer.
- **How:** File as a bead/mission against the AgenC repo — the *what* is "a failed or notification-less cron run must produce a visible failure signal"; the *how* belongs to AgenC (it knows whether that's daemon-level exit-status watching, a sweeper cron, or notification-expectation metadata).
- **Impact:** high — converts silent multi-week outages into next-day fixes, fleet-wide.
- **Confidence:** certain.

- **Why:** The [auto-mode-default post](https://claude.com/blog/auto-mode-default-in-claude-code) says auto mode became the default on 08-14 with the classifier now free, plus new fallback behavior (reverts to manual after 3 consecutive blocks). ### 3. Exobrain: build the scheduled self-improvement loop (the Warp/ABC pattern)

- **What:** A new cron + skill pair — a scheduled "improver" that mines accumulated feedback and proposes guidance edits. The missing sibling of `/self-refine`.
- **Why:** Two independent posts converge on the same architecture: [Warp's dual-skill loop](https://claude.com/blog/how-warp-builds-self-improving-agents-on-claude) (base skill works; improver skill runs on a schedule, mines persistently-stored human feedback, proposes minimal skill edits via PR) and [ABC Legal's harvester-tuner](https://claude.com/blog/how-abc-legal-turned-every-employee-into-a-builder-with-claude-managed-agents) (harvester collects reactions/replies hourly as labeled data; tuner proposes changes weekly). This is MECA's stated ideal — "Claude doing its own self-improvement" — as a concrete mechanism. Kevin's setup has all the ingredients but not the loop: `/self-refine` is session-scoped and manually invoked; corrections logged in the AI journal and mission transcripts evaporate unless someone reads them; the Guidance-Edit Gate already provides the human-review chokepoint the pattern requires (the improver's edits would flow through the judge). The claude-news-processor's own Standing Calibration Rules section is the one existing instance of this pattern — generalize it.
- **How:** The insight for a dotfiles/exobrain mission: (1) harvest — a cron sweeps recent mission transcripts + AI journal for correction-shaped signal (Kevin pushback, repeated friction, hook blocks) into a persistent structured store; (2) tune — a second cadence reads accumulated signal, identifies the skill/rule each pattern implicates, and proposes minimal edits (via the writeable-copy dotfiles repo, gated by the guidance judge), citing which signals prompted each change, Warp-style. Key Warp details worth keeping: feedback stored persistently because "feedback typically disappears when sessions end"; edits minimal and reviewable; principle-level fixes over instance patches (the startups guide's Cainex loop: "fix the principle, not the example").
- **Impact:** high — this is the compounding-returns lever; every future agent gets the corrections every past agent earned.
- **Confidence:** likely.

### 4. CLAUDE.md doctrine: metabolize the Claude 5 context-engineering rules — and hold the tension with "harness as law"

- **What:** `/prompt-engineer` and `/cc-global-instructions-management` doctrine; eventually the global CLAUDE.md itself.
- **Why:** The [context-engineering post](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models) is the strongest guidance-writing signal Anthropic has published this cycle: 80%+ of Claude Code's system prompt removed for Claude 5 models with no loss; prescriptive rules replaced by judgment-based guidance ("match surrounding code" vs "never write multi-line comments"); CLAUDE.md as overview-plus-gotchas; tool interfaces made expressive instead of example-laden. But [Outtake's lesson](https://claude.com/blog/how-outtake-built-a-cyber-investigator-on-claude) pulls the other way: in long sessions "every single word in that prompt will probably be ignored eventually" — critical behaviors belong in the harness, not the prompt. Kevin's architecture is already the synthesis these two posts triangulate: hooks/judges for gates (harness as law), prose for judgment, and a Patch Register whose entries are armored *because softer versions empirically failed*. So the move is not "delete 80% of CLAUDE.md" — it's: (a) fold the judgment-over-prescription style into `/prompt-engineer`'s doctrine for *new* guidance, and (b) for existing rules, apply the Patch Register's own placement principle — any rule that exists because prose kept failing is a candidate to become a hook, not a candidate for softening. Note: this is supplementary source material for the P-3 register entry's cached article, not its retest trigger (P-3 fires at the next model class).
- **How:** Dotfiles mission carrying both post URLs and this framing; let `/prompt-engineer`'s own doctrine decide what to absorb.
- **Impact:** high — affects every future guidance artifact.
- **Confidence:** likely.
