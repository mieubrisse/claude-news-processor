Blog Digest
-----------

**[The evolution of agentic surfaces: building with Claude Managed Agents](https://claude.com/blog/building-with-claude-managed-agents)** — Anthropic positions Claude Managed Agents as the production platform that decouples the agent "brain" (reasoning loop) from its "hands" (execution sandbox). The mechanical innovations worth naming: credentials live in vaults outside the sandbox; the reasoning loop starts before container spinup, cutting p50 time-to-first-token by ~60%; sessions persist event histories for resumption and observability. Three core resources — Agents (config), Environments (Anthropic-managed or self-hosted), Sessions (isolated sandbox runs) — plus Memory and Dreaming (pattern extraction *between* sessions), MCP tunnels for private-network access, and permission policies.

**[New in Claude Managed Agents: scheduled runs and vault env vars](https://claude.com/blog/whats-new-in-claude-managed-agents)** — Two beta additions: cron-style scheduled triggers (each run starts a fresh session; pause/resume/archive controls) and environment variables held in vaults. The vault env-var mechanic is the interesting half: the agent only ever receives a *placeholder*; the actual credential is attached at the network boundary, only on requests to approved domains; running sessions auto-pick up key updates without restart. Compatible with CLIs like Browserbase, KERNEL, Notion, Ramp, Sentry — anything that authenticates via HTTP headers.

**[Building intelligent apps for Apple platforms with Claude in the Foundation Models framework](https://claude.com/blog/claude-for-foundation-models)** — A Swift package that lets iOS/macOS apps route between Apple's on-device Foundation Models framework and Claude. The pattern: use on-device models for fast typed extraction (`@Generable` annotations return typed Swift values), hand off structured outputs to Claude for multi-step reasoning, stream Claude's response back into the same view. Layered intelligence by workload — match each computational step to the most efficient tool. iOS 27+ / macOS 27+ / visionOS 27+ etc.

**[Observability for developers building connectors](https://claude.com/blog/observability-for-developers-building-connectors)** — Dashboard for published MCP connector authors: active users, total tool calls, directory ranking, health scores, error rates, latency with per-tool breakdowns, and which Claude surface (Claude / Claude Code / Cowork) drives engagement. Plus in-app MCP-server submission to the directory. Admin/Owner roles on Team/Enterprise plans required; 300+ connectors in the directory.

**[The Claude Cowork product guide](https://claude.com/blog/the-claude-cowork-product-guide)** — Positioning piece for Cowork: a knowledge-work agent that automates multi-step tasks across applications, distinct from chat-style drafting. Local file access, Slack/Drive/connected-services integration, subagents for delegation, long-running work, scheduled tasks, and a "plugins system" for domain-specific work (marketing, PM). Seven common workflow patterns: research briefs, meeting prep, recurring reports, etc.

**[How one Anthropic seller rebuilt his team's workflows with Claude Code](https://claude.com/blog/how-anthropic-uses-claude-gtm-engineering)** — Sales-leader-with-no-coding-background built CLAFTS (Claude Drafts), a Gmail-integrated drafting tool: ~4,300 LOC mostly generated by Claude Code, system prompt iterated "hundreds of iterations" to match his voice, pattern-matches tone across customer/peer/personal communications, pulls context from Drive and third-party tools. Scaled into Daily Brief (calendar + web search on attendees + CRM-via-MCP), Daily Recap, and Cowork plugins like `/customer-context` and `/pipeline-management` — 80% team adoption within months. Headline mechanic: system prompts require hundreds of iterations to hit voice fidelity.

### AgenC Config

**[Medium impact, Speculative]** Consider whether AgenC's secrets management benefits from a "credential at the network boundary, never in the agent context" pattern, modeled on Managed Agents' vault env vars. Right now AgenC missions inherit shell environment and can read `.env` files (with hook denials around the most sensitive paths). The Managed Agents pattern is structurally stronger: the agent literally never holds the secret value; it sees a placeholder, and a network-level interceptor swaps in the real value only for approved-domain requests. The honest tradeoff: implementing this for AgenC is non-trivial (proxy infrastructure), and Kevin's solo-founder threat model rarely exposes credentials beyond his own machine. Worth noting because the architecture is interesting; not worth building until a specific incident motivates it.

- **What:** Architectural note in the AgenC roadmap, not an immediate build.
- **Why:** Standing Calibration Rules say to surface "how does this mechanism actually work" hooks at depth; the network-boundary credential swap is exactly that kind of mechanical detail worth knowing about.
- **How:** No action unless a future credential-exposure incident makes it concrete.
- **Impact:** Medium if ever needed; low in the current threat model.
- **Confidence:** Speculative.
