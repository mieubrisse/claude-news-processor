### Directly relevant to your Claude Code setup

**[How Claude Code works in large codebases: Best practices and where to start](https://claude.com/blog/how-claude-code-works-in-large-codebases-best-practices-and-where-to-start)**
Anthropic's most prescriptive guide yet on Claude Code config hygiene. Frames the "extension harness" as CLAUDE.md (load-every-session, keep minimal), hooks (event-triggered), skills (on-demand), plugins (always-available bundles), LSP, MCP, and subagents — and gives explicit anti-patterns: overloading CLAUDE.md with reusable expertise, using prompts for repetitive tasks, exploration and editing in the same session. Key prescription: review configurations every three to six months after major model releases, because instructions optimized for previous models can become *actively constraining*.

**[Agent view in Claude Code](https://claude.com/blog/agent-view-in-claude-code)**
Claude Code CLI now ships a native multi-session dashboard: `claude agents` (or left-arrow from any session) shows all active agents with status indicators, last message preview, and inline reply. New flags: `claude --bg [task]` launches a background session; `/bg` backgrounds an active one. This is Anthropic's native parallel-agent UX — overlapping with what AgenC does, with a different design philosophy (lightweight session multiplexing vs AgenC's full mission isolation).

**[Redesigning Claude Code on desktop for parallel agents](https://claude.com/blog/claude-code-desktop-redesign)**
Claude Code desktop app gets a sidebar for managing multiple sessions across repos, integrated terminal/editor/diff viewer, side-chat shortcut (⌘;) for mid-task conversation branches, three view modes (Verbose/Normal/Summary), and macOS SSH support. Most of this is desktop-app-specific (not the CLI you use inside AgenC).

**[Best practices for computer and browser use with Claude](https://claude.com/blog/best-practices-for-computer-and-browser-use-with-claude)**
Optimization guide for computer/browser-use tool. Top finding: pre-downscale screenshots before API submission, because images exceeding model limits get silently downscaled and cause coordinate mismatches. Claude 4.6 family: 1568px long edge / 1.15 MP. Opus 4.7: 2576px / 3.75 MP. Recommended default: 1280×720. Also: place text instruction *before* the image in message arrays; for Opus 4.7 use `high` thinking effort as default; pair cache breakpoints with a rolling buffer of 3 recent screenshots. Tangentially relevant — your `/website-screenshotting` skill uses `shot-scraper` for one-shot captures, not interactive browser use, so most of this doesn't apply unless you build interactive browser-use skills.

### Skills

**1. Periodic config-tuning review (high impact, certain)**

- **What:** Establish a recurring review of your global CLAUDE.md, top-level skills (`/about-me`, `/my-artistic-taste`, `/storytelling`, etc.), and hooks against the currently-installed Claude model. Could be a new `/audit-claude-config` skill, a scheduled `/loop` job, or simply a beads issue.
- **Why:** Anthropic now states explicitly that "instructions optimized for previous models may become actively constraining" with newer ones. Your global CLAUDE.md is *large* (thousands of lines including the AgenC operating section, the user instructions, and routing rules). Some of it was tuned for older models. ([How Claude Code works in large codebases](https://claude.com/blog/how-claude-code-works-in-large-codebases-best-practices-and-where-to-start))
- **How:** A self-refine-style skill that reads the current CLAUDE.md, identifies rules that are likely vestigial (compensating for model limitations no longer present), and proposes deletions. Alternatively, schedule via `/schedule` to run every quarter.
- **Impact:** High — your config is the foundation every mission inherits. Drift compounds.
- **Confidence:** Certain — Anthropic explicitly recommends this cadence.

**2. CLAUDE.md slimming pass (high impact, likely)**

- **What:** Audit your global CLAUDE.md for content that should be skill-resident rather than always-on.
- **Why:** Anthropic's prescription: "Keep root [CLAUDE.md] files minimal, providing pointers and critical gotchas only." "Move complex logic to skills instead." Your CLAUDE.md inlines a lot of operational detail (git workflow rules, software-engineer routing, journal/Todoist conventions, full skill routing index) that loads on every turn of every mission. Most of it is already a "pointer-to-skill" — but some sections (the full git workflow, the rebase ours/theirs table, the auto-mode reshaping section) are dense always-on context. ([How Claude Code works in large codebases](https://claude.com/blog/how-claude-code-works-in-large-codebases-best-practices-and-where-to-start))
- **How:** Spawn a mission to `mieubrisse/dotfiles` asking it to identify which CLAUDE.md sections could be moved into on-demand skills without losing the trigger guarantee. Caveat: some sections (Tier 0 truth-seeking, Plan Mode rule, Auto Mode reshaping) are deliberately always-on because they override training priors — those must stay.
- **Impact:** Medium-high — reduces every turn's context cost; lets newer skills load with less competition.
- **Confidence:** Likely — there's tension between "minimal CLAUDE.md" and "ensure rules fire reliably." The right answer is some trim, not a wholesale move.

**3. Subagent-for-exploration discipline (medium impact, likely)**

- **What:** Add a routing rule or skill that says: when exploring an unfamiliar codebase or doing broad research, dispatch to a subagent rather than reading in the main session.
- **Why:** Anthropic calls out "exploration and editing in same session" as a top mistake — it pollutes context and degrades editing. You already have `Explore` and `general-purpose` subagents available; this is about reinforcing the *habit* of using them, not adding capability. ([How Claude Code works in large codebases](https://claude.com/blog/how-claude-code-works-in-large-codebases-best-practices-and-where-to-start))
- **How:** Either a CLAUDE.md line under a new "Exploration vs Editing" section, or fold into the existing `/software-engineer` skill so it routes exploratory questions through Explore before suggesting edits.
- **Impact:** Medium — codebase-quality effect on multi-step engineering tasks; less relevant for short tasks.
- **Confidence:** Likely — the principle is sound, but you may already do this reflexively, in which case a written rule adds overhead without changing behavior.

### Hooks / Skills (parallel-agent UX)

**4. Evaluate `claude agents` vs AgenC overlap (medium impact, speculative)**

- **What:** Decide whether the native `claude agents` view (and `claude --bg` / `/bg`) changes anything about how you run AgenC missions, or whether AgenC's tmux-window-per-mission model remains the right abstraction.
- **Why:** The native CLI now ships a lightweight multi-session manager that overlaps conceptually with what AgenC does — but at a different abstraction level. AgenC gives full mission isolation (clone, config, tmux window); `claude agents` gives lightweight session multiplexing inside one Claude install. The two can coexist; the question is whether `claude --bg` lets you skip spawning a new mission for some tasks. ([Agent view in Claude Code](https://claude.com/blog/agent-view-in-claude-code))
- **How:** Try `claude --bg "quick task"` from within an AgenC mission for a small task; see whether the bg session feels usable or whether the lack of isolation is worse than spawning a new mission. Likely conclusion: AgenC stays primary for cross-repo work; `--bg` could be useful for fire-and-forget tasks inside one repo.
- **Impact:** Medium — could simplify some workflows; doesn't replace AgenC.
- **Confidence:** Speculative — depends on how well the feature works in practice and whether the bg session UX feels right to you.
